## 先复现、后修复

`test/merge-readiness.test.cjs` 第一组 12 项在旧实现全部失败，修复后通过：

- loadData 尚未完成时停用插件，旧初始化仍继续创建服务；注册失败遗留已创建资源。
- 一个视图清理抛错会阻断后续网络/凭据关闭；重复停用重复发送生命周期通知。
- 旧名称 .pdf 改为 .mp4 后默认打开器仍按旧扩展名选择；扩展名 constructor 误取原型属性。
- 外部打开器的 canOpen 收到未冻结、未经字段裁剪的元数据。
- 重复处理同一 DOM 链接会绑定多份点击事件；停用未还原自动名称，重新启用时可能被当作自定义名称。
- 查询返回后覆盖已被其他渲染器重新使用的链接；关闭动态名称未约束旧观察器。
- 100 次悬停重复创建 100 个渲染等待者（底层缓存可能合并网盘调用，但 UI 层仍有额外负担）。

第二组补充 8 项。第一轮修复后其中 6 项通过、2 项失败：自定义标题仍自动查询；不符合同步契约的 canOpen 返回拒绝 Promise 时产生未处理错误。这两项随后修复。其他用例覆盖自定义名称、共享一次元数据读取、无原始 title 的还原、关闭后的观察器、原生链接点击，以及能力检查中注销打开器。

## 实现与性能

- `link-view.cjs` 分离阅读视图逻辑，使用 WeakMap 记录 DOM 所有权；停用释放监听与观察器，并只还原仍属于本插件的显示值。
- 单个链接最多一个在途渲染等待者；自定义标题和富文本标签不自动查询，仅在用户主动悬停/点击时按需解析。
- 默认打开器先取最新元数据再选择扩展名，无第二次 filemetas 请求；打开器调用前再次核对注册身份与取消信号。
- 原有 HTTP 3/64、名称 2/32、元数据 256 项/120 秒预算保持不变。没有新增依赖、扫描、持久索引、常驻服务或定时轮询。

自动验证：`npm run check`，154 项通过、0 失败、0 跳过（本地 Linux / Node 22.16.0）。合成性能继续检查 500 个相同资源的一次读取、缓存上限、空闲零请求和 160 KiB 包体预算。Windows 上原有两个符号链接专项可能按权限跳过，以对应 CI 日志为准，不把跳过计为通过。

构建可重复性以连续两次 main.js/manifest.json/styles.css 的 SHA-256 对比验证。测试使用宿主/DOM 替身及本机回环服务，不是原生 Obsidian 或真实账号测试。

# 设计约束

需求来源：2026-11-18 的已确认讨论。独立工具、百度优先、个人使用；不再次扩大首版范围。

1. 文件身份与元数据分离：provider + account ID + file/folder ID 稳定寻址，路径用于网盘导航。最新名称仅渲染，手改标题保留，不修改 Markdown。文件内容默认当前版本。
2. 不理解作品，不做资源副本识别。MediaCore 管理作品关系；漫笺链接显式导入，不反查书库。
3. 原生快速引用窗口和轻量动态目录，不做 VFS、大型播放器、主库同步或持久搜索索引。
4. 搜索只调用官方关键词接口并限定当前子树。API 权限失败明确报告，不递归扫描补齐。分页和筛选的覆盖范围必须写清。
5. 可替换授权提供者与文件适配器分离。OpenList 自动授权使用随机 state、固定回调、隔离临时会话；缺少宿主能力时手动入口，不降低安全设置。
6. 凭据同步为用户明确选择的 Vault 明文模式；未实现之前讨论但未确认的跨设备密钥导入。普通文件同步不是分布式锁。
7. 移动后的 ID 解析失败时由用户重选，不自动猜同名替代。插件不为了恢复引用而自动遍历网盘。
8. 所有功能须有取消和资源释放路径。凭据轮换的事务生命周期与单个 UI 等待者分开，只有明确未发出才回退恢复标记。

## 模块

- reference：协议、路径、Markdown、名称、无损 JSON 数字、MediaCore 候选。
- runtime：请求队列、有界元数据缓存、可见名称低优先级调度。
- transport：固定 HTTPS 读取/授权端点、响应/超时限制、发送阶段标记、授权跳转信封读取。
- auth/storage/oauth：授权提供者、凭据状态机、原子文件替换、OAuth state 与隔离窗口。
- baidu/service：ID 解析、分页浏览、服务端搜索、统一资源与外部打开器。
- ui/main：快速窗口、命令、斜杠菜单、阅读视图与公共 API。

## 未进入本版的已知需求

图片/PDF/影音轻预览、缓存容量配置、用户确认的下载、完整文件管理、115 和 AI 分级权限仍在后续范围。未实现不等于取消需求。本轮先把核心能力、测试、诊断和发布门槛落实，不用未完成的大功能充当稳定性。

## 自动验证

执行 `npm run check`：语法、版本、Node 测试、构建和合成性能约束。GitHub workflow 对 Linux/macOS/Windows 执行相同命令，并保存 dist/ 构建与哈希。源代码与线上 CI 最终结果应以对应提交为准，不把“已配置 workflow”写成“已通过”。

覆盖范围：

- 协议/Unicode/大整数、文件夹 ID 与路径冲突、默认名称/自定义名称、MediaCore 无凭据交接。
- 普通关键词搜索分页、子树过滤、权限失败不递归扫描、重复和无进展分页。
- TLS 前失败与发送后未知结果、Token 单次重试与并发轮换、成对持久化、旧结果不覆盖同步新版本。
- OAuth state/重复参数/回调来源/重放/取消/超时、隔离窗口安全选项、不会导航到带 Token 的结果页。
- 授权后验证失败保留候选用于重试，关闭窗口丢弃迟到结果。
- 原子文件替换、坏账号隔离、目录/文件限额、Vault 下符号链接拒绝。
- 请求/响应/队列上限，500 个同资源消费者仅一次加载，可见名称并发 2，缓存 256 项，卸载清理。
- 快速窗口输入防抖、旧行失效、分页、大小筛选、100 次开关无注册残留。
- 回环端到端：授权交换 → 账号校验 → 凭据保存 → 搜索 → 重命名/移动后解析 → 并发续期 → 新对象恢复凭据。

回环测试把允许的 HTTPS 请求重定向到本机 HTTP 夹具，并模拟 TLS 就绪事件；它验证生产模块组合与消息流程，**不验证真实 TLS、百度平台、OpenList 在线服务或原生登录 UI**。原生窗口使用宿主接口替身。Windows 缺少符号链接权限时专项测试明确跳过，不算通过。

`dist/performance.json` 为 Node 核心合成数据。堆差值和模块加载耗时受进程/文件缓存影响，不是 Obsidian 的空闲占用、启动增量或真实 UI 帧率。

## 必须补齐的真实验收

在独立测试 Vault 中完成并在 acceptance.json 附证据；不得直接把 not-run 改为 passed。

| Gate | 场景 |
|---|---|
| baidu-live-auth | 实际 OpenList 官方授权/账号确认/保存、拒绝授权、关闭窗口和续期；核对服务适用范围 |
| baidu-live-search | 使用实际签发 Token 搜索指定目录及子目录、中文关键词、至少两页、无权限时不扫描 |
| folder-move | 文件及文件夹重命名/移动/父目录移动、删除/恢复；错误路径不能绑定同名替代对象 |
| obsidian-macos | 真机命令、斜杠菜单、键盘、右键、阅读视图、隔离窗口、浏览器目录定位 |
| obsidian-windows | 同上，并验证文件原子替换、外部打开器能力检测 |
| credential-sync | 坚果云同步新凭据、两端并发续期、断网、冲突副本、恢复标记及重新授权 |
| obsidian-performance | 固定 Vault 对照启用/禁用：冷启动、长笔记、开关窗口、空闲、插件卸载，记录 RAM/CPU/请求数 |

稳定版候选的代码可以安装测试，但在这些证据缺失时 `npm run release-check` 必须失败。未来预览、115、写操作各自需要额外验收，不能借用本表证明它们稳定。

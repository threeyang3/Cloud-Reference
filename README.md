# Cloud Reference

独立、按需运行的 Obsidian 网盘资源引用工具。**0.2.0 稳定候选版：不等同于已完成真实账号、双设备和 Obsidian GUI 验收的稳定发布。** 发布检查见 [验收状态](docs/acceptance.json)。

百度网盘优先。MediaCore 负责作品与资源关系；本插件只提供账号、文件身份、浏览、搜索和打开接口。不依赖漫笺、不识别作品、不同步主库、不建立持久搜索索引。

## 0.2.0 能力

- 命令面板“插入网盘资源”，或输入 `/网盘`、`/cloud` 打开快速选择器。
- 多账号、文件/文件夹引用、轻量目录浏览、返回和分页、键盘选择。
- 百度普通关键词搜索 `method=search`，搜索当前目录及子目录，50 项一页；类型和大小筛选仅作用于当前页。不扫描全盘，不偷偷退化为递归抓取，不要求语义搜索。
- 普通 Markdown 保存账号、文件/目录 ID、名称和路径快照。阅读视图按需显示最新名称；手改标题保留，Markdown 原文不修改。
- 文件默认在网盘网页定位所在目录，文件夹默认打开轻量目录窗口。按扩展名配置外部打开器，右键临时选其他动作；不自动下载。
- OpenList 官方网页授权：在宿主支持时使用隔离窗口自动接收授权结果，校验随机 state；不支持时有手动令牌入口。取得凭据后先验证账号，用户确认后保存。
- 凭据更新按请求阶段区分“未发出”和“结果不确定”。单进程续期合并、成对保存、最新同步文件重读和恢复标记，限制并发冲突影响。
- API v1、TypeScript 接口、MediaCore 候选交接示例与无敏感数据的性能诊断。

## 构建与安装

Node.js 22+；无第三方 npm 构建、测试或运行时依赖，无需 `npm install`。

```sh
npm run check
```

生成 `dist/main.js`、`manifest.json`、`styles.css`、`SHA256SUMS` 和合成性能报告。把前三个文件放入**独立测试 Vault** 的 `.obsidian/plugins/cloud-reference/` 后启用插件。主库继续由坚果云同步。

GitHub 检查会在 Linux、macOS、Windows 构建并上传各自安装文件。检查通过不代表真实网盘或 GUI 验收通过；请先完成 [人工验收](docs/VALIDATION.md)，再使用正式主库。

## 授权与跨设备

运行“连接百度网盘”，选择“开始官方网页授权”。授权确认页面的应用身份属于 OpenList，不是已独立获批的 Cloud Reference 应用。请阅读页面实际权限；插件只使用读取接口，并不意味着 OAuth 授予的权限也是只读。

隔离授权窗口会禁用 Node、启用 sandbox/contextIsolation，拒绝新窗口、下载和权限请求，关闭后清理会话。它依赖桌面宿主暴露的 BrowserWindow 能力；缺少此能力或平台不允许嵌入登录时，使用“手动授权”。不会为此安装远程模块或降低安全设置。

OpenList 服务接触授权码与续期凭据；网盘数据请求直连百度。服务适用范围与长期使用许可须另行确认，不把个人使用等同于获批分发。

默认新连接只在当前会话保存。明确勾选后，可以把**明文凭据**保存于：

```text
.obsidian/plugins/cloud-reference/accounts/<账号ID>.credentials.json
```

此文件可随坚果云同步，使另一台设备复用账号，不需要手工输入第二份 Token。**这不是加密存储；拿到 Vault 副本的人或其他插件可能访问账号。** 不要将账号文件、备份、Token、Cookie 或回调 URL 提交到 GitHub、日志或问题报告。

每次访问读取本机当前文件，但插件不能强制坚果云立即同步，也没有跨设备原子锁。收到未知续期结果会保留恢复标记，避免再次使用可能已消费的 Refresh Token；先等待同步并重试，仍无法恢复再重新授权。偶尔失效仍可能发生。

## 引用与显示

```markdown
[教材.pdf](obsidian://cloud-reference?v=1&provider=baidu&account=123&id=456&kind=file&path=%2Fcourse%2Fbook.pdf&name=%E6%95%99%E6%9D%90.pdf "/course/book.pdf")
```

示例身份是虚构值。默认名称以 URI 中原名称作比较；手改 Markdown 标签后保留该标签。阅读视图动态名称不改正文，源码与 Live Preview 暂不做动态名称替换。

按 ID 获取当前元数据与路径；文件/目录 ID 失效时，不自动复用旧路径上的同名对象。右键可重新选择并复制替代引用，人工替换原链接。目录 ID 是否能在实际授权下持续解析，以及移动、删除恢复后的行为，都在真实验收范围内。

网页使用浏览器自己的登录态，需要确认与插件账号一致。卸载插件后 Markdown 与身份仍在，重新安装并恢复授权可以重新解析。

## 性能约束

| 项目 | 代码约束 |
|---|---:|
| 启动、空闲 | 无网盘请求、无扫描、无周期轮询 |
| HTTP 并发 / 等待队列 | 3 / 64 |
| HTTP 阶段超时 / 响应上限 | 20 秒 / 2 MiB |
| 可见名称更新并发 / 等待队列 | 2 / 32 |
| 元数据内存缓存 | 256 项 / 120 秒 |
| 目录与搜索分页 | 每页 50 项 |
| 搜索防抖 | 400 毫秒 |
| 目录返回历史 | 最多 64 层 |

名称自动更新超过预算时保留原标签，悬停或点击可按需更新；同一资源请求合并。窗口关闭、查询替换、插件卸载均取消相关工作。已发出的凭据轮换独立于单个 UI 等待者完成成对保存，插件卸载则停止并保留必要恢复标记。

`npm run bench` 是 **Node 核心合成测试，不是实际 Obsidian RAM/CPU 基准**。运行“复制性能诊断”可取得请求数、队列、缓存和生命周期计数；不包含账号、路径或凭据。

## 当前边界

尚无媒体预览、上传/重命名/移动/复制/删除、115、移动端或 MCP 服务。核心链路可靠性优先，不通过堆叠功能宣称稳定。

MediaCore 可调用本插件 API；现有候选协议输出它已支持的网页备用入口，稳定引用另行返回给适配器。**尚未修改 MediaCore 仓库或声称双向 UI 已联调完成。** 漫笺链接由用户直接导入，不向漫笺查询文件。

`npm run release-check` 在真实验收证据未齐全时会失败，阻止把候选构建称作稳定发布。
